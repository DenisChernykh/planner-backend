# Ритм — интерфейс

React-клиент для личного планирования по месяцам. Сейчас в нём доступны shell
планировщика, создание цели, минимальные экраны плана и корзины. API-контракт
принадлежит соседнему Hono backend и использует `/api`, Telegram OIDC и RFC 9457
Problem Details.

## Маршруты

- `/` — переход к текущему месяцу;
- `/plans/:month` — план выбранного месяца;
- `/plans/:month/goals/new` — создание цели;
- `/plans/:month/trash` — корзина месяца;
- `/plans/:month/connections` — создание и отзыв ключа личного ChatGPT-плагина.
- `/plans/:month/reminders` — подключение Telegram, часовой пояс, тихие часы и расписания целей.

Месяц передаётся в формате `YYYY-MM`. Некорректный месяц и неизвестный маршрут
показывают отдельное понятное состояние.

## Монолит

Интерфейс и Hono API публикуются одним Worker `app`. SPA обслуживается Static
Assets; `/api/*` вызывается на том же origin без промежуточного Worker.
Конфигурация находится в `../backend/wrangler.jsonc`.

## Авторизация

При AUTH_MODE=telegram frontend запрашивает GET /api/auth/me: ответ 401 UNAUTHENTICATED ведёт на /login, а кнопка запускает browser redirect на /api/auth/telegram/start. После callback backend должен перенаправить браузер на корень frontend Worker через AUTH_SUCCESS_REDIRECT_URL.

При AUTH_MODE=disabled Hono возвращает 404 NOT_FOUND не только для Telegram endpoints, но и для защищённого /api/notes/*. Frontend распознаёт этот контракт и показывает состояние отключённой авторизации, не подменяя его ложным публичным режимом.

## Локальная разработка

Основной запуск из корня: `pnpm install --frozen-lockfile`,
`pnpm db:migrate:local`, `pnpm dev`; открыть `http://localhost:8787`.

Для HMR из корня запустите `pnpm dev:api` и `pnpm dev:ui` в двух терминалах.
Vite на `http://localhost:5173` проксирует API в локальный Worker на порту 8787.
`DEV_API_PROXY_TARGET` в `.env.local` позволяет изменить адрес локального API.

## API contract

`openapi/openapi.json` генерируется непосредственно из Hono `createApp()` в
`../backend`; запущенный HTTP-сервер для этого не нужен. После изменения
контракта выполните:

```bash
pnpm api:update
```

Команда сначала обновляет snapshot, затем запускает Orval. Generated
TypeScript/Zod-файлы вручную не редактируются. Sync проверяет наличие всех
Planning operations, которые использует frontend.

## Цели

Форма поддерживает четыре способа учёта: `check`, `quantity`, `scale` и `time`,
а также периоды `day`, `week` и `month`. Для `time` обе границы необязательны:
можно разрешить любое время, задать только «не раньше», только «не позже» или
обе границы. Диапазон с началом позже конца проходит через полночь. Недельная
частота ограничена 1–7, месячная — фактическим числом дней выбранного месяца.

## Проверка

```bash
pnpm test
pnpm build
pnpm check
```

`pnpm check` обновляет и проверяет API snapshot, формат, lint, архитектурные
границы, тесты и сборку SPA. Полный gate монолита запускается из корня.

## Deploy

Из корня: `pnpm deploy:dry-run`, а для явно разрешённой публикации —
`pnpm deploy`. Первый переход описан в
[инструкции миграции](../docs/monolith-migration.md).

## Telegram-напоминания

Раздел «Напоминания» доступен в боковой навигации. Общие настройки применяются
ко всему плану; режим, время и дни недели задаются для каждой цели месяца.
Подключение требует одноразовой ссылки и подтверждения в личном чате бота.
Если backend-бот отключён, страница позволяет сохранить настройки заранее.
Часовой пояс из настроек используется при переходе на текущий месяц.

## UI в ChatGPT

`chatgpt.html` и `src/app/chatgpt/main.tsx` — отдельная точка входа того же UI.
Она использует общие routes с memory router, общие страницы и API hooks;
`createChatGptAdapter` вызывает именованные инструменты через MCP Apps bridge.
Браузерная версия продолжает обращаться к `/api` на том же origin.
Сборка `pnpm chatgpt:build` из корня; [подключение](../chatgpt/README.md).
