# Напоминания и ввод данных через Telegram

Дата: 29 сентября 2026 года.
Статус: концепция для первой версии; ещё не реализована.

## Задача

Напоминать о заполнении целей в подходящее время и позволять сразу внести
данные ответом на сообщение или одним нажатием, без поиска цели в меню
и перехода на сайт.

## Когда присылать

Время напоминания настраивается отдельно для каждой цели. Утренние события,
например пробуждение и завтрак, запрашиваются утром после обычного времени
события. Вечер подходит для итогов дня и сбора оставшихся незаполненных данных.

Нужно различать «напомнить сделать» и «напомнить записать». Первая версия
сосредоточена на записи данных: время события и время запроса могут отличаться.
Например, о времени пробуждения можно спросить в 09:00, а записать ответ 07:40.

Предлагаемые режимы для каждой цели:

- Без напоминания.
- В выбранное время.
- В вечернем сборе.

Вечерний сбор — одно общее напоминание о незаполненных целях. Он также может
включать цели, для которых ранее уже был отправлен вопрос, но ответ не получен.
Цели с режимом «Без напоминания» в сбор не включаются.

## Как вносить данные

| Тип данных | Пример вопроса | Ввод |
| --- | --- | --- |
| Отметка | Позавтракал? | Кнопка «Да» |
| Время | Во сколько сегодня проснулся? | Ответ `07:40` |
| Количество | Сколько страниц прочитал? | Ответ `25` |
| Шкала | Как прошёл день? | Кнопки со значениями шкалы цели |

Пример диалога:

> Бот, 09:00: Во сколько ты сегодня проснулся?
>
> Пользователь: 07:40
>
> Бот: Записал: сегодня, пробуждение — 07:40. · Исправить

Для текстового ввода можно использовать Telegram ForceReply, который включает
режим ответа на вопрос бота. Для отметок и оценок — кнопки под сообщением.
Ответ сохраняется как запись соответствующей цели в планере.

Документация: [ForceReply](https://core.telegram.org/bots/api#forcereply),
[InlineKeyboardMarkup](https://core.telegram.org/bots/api#inlinekeyboardmarkup).

## Правила поведения

- Уже внесённые данные не спрашивать повторно, включая записи с сайта.
- Связывать ответ с конкретным вопросом, целью и датой, а не просто с последним
  сообщением бота. Ответ на вчерашний вопрос сохранять за вчерашний день.
- После сохранения кратко подтверждать цель, дату и значение; дать возможность
  исправить запись.
- Дать возможность отложить вопрос.
- Учитывать часовой пояс пользователя и тихие часы.
- Вечером отправлять одно напоминание о пропусках, только если они остались.

## Границы первой версии

Включить настройки напоминаний для цели, отправку по расписанию, сохранение
ответов для четырёх существующих типов данных и вечерний сбор пропусков.
Не требовать свободного распознавания произвольных фраз: время и число можно
вводить коротким ответом в ожидаемом формате.

Перед реализацией уточнить:

- Где пользователь задаёт часовой пояс, тихие часы и время вечернего сбора.
- Как вводить несколько пропущенных значений из одного вечернего сообщения
  с минимумом действий.
- Как работают откладывание и исправление записи.
- Что делать с поздним ответом, если запись за эту дату уже появилась на сайте.
- Как связать Telegram-чат с владельцем целей и подключить напоминания.
- Как запускать отправку по расписанию с учётом ограничений инфраструктуры.
  В `backend/AGENTS.md` добавление Cron требует отдельного решения по проекту;
  этот документ фиксирует продуктовый сценарий, но не выбирает инфраструктуру.

## Состояние проекта на дату записи

В модели планирования уже есть типы `check`, `quantity`, `scale` и `time`.
Telegram-бот пока обрабатывает только `/start`. Расписание уведомлений,
привязку ответов к целям и сохранение данных из Telegram нужно реализовать.
