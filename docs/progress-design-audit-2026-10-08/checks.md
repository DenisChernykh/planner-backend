## Воспроизведение

Целостность матрицы и сохранённых доказательств:
`node docs/progress-design-audit-2026-10-08/verify-evidence.mjs` из корня.
Она проверяет ссылки, ревизию исходников, результаты и размеры PNG приложения;
повторный функциональный gate и внешние проверки эта команда не заменяет.

Node 24, pnpm 11.15.1, установка из корня с `pnpm install --frozen-lockfile`.
Для P: `pnpm --dir frontend exec tsx ../docs/progress-design-audit-2026-10-08/verify-calculations.ts`.
Для A: `pnpm --dir backend exec vitest run test/progress-acceptance.spec.ts test/app.spec.ts`.
Для B/снимков запустите Vite на `127.0.0.1:5188`, затем аналогично P запустите
`verify-browser.ts` / `capture-design.ts`, передав путь к установленному Playwright.
API перехватывается только на loopback; эти сценарии не контактируют с production.
Для Pen откройте исходный `Planner.pen` в Pen, запускайте `capture-pen.mjs` из папки
исходного документа с абсолютными путями к MCP SDK и открытому документу.
Сценарий сохраняет только наблюдения слоёв, без PNG макетов.
`compare-design.ts` использует временные MCP-снимки и пишет объединённое сравнение
только во временную папку вне репозитория. Старые browser-results/browser-supplement
и baseline-requirements — исторические диагностики исходного аудита, не итог.
